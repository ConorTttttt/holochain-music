### Targeted remediation PRs to propose, **not implemented without approval**

- **Security PR A (highest priority):** Add an opt-in, disposable **three-agent cross-class quota test** (20 requests + 20 grants from one sender, then multiple agents near 500+500/hour) and a long-history query-cost measurement. Initially tests/benchmark only. Separate any later coordinator change to enforce a shared quota; its deployment must document DNA hash/version compatibility, coexistence with existing private entries and failure/retry semantics. Do **not** delete chain history or silently change limits.
- **Security PR B:** Add Python outbox error-classification regression cases covering explicit refusal text embedded in a network/timeout wrapper, generic bridge disconnection, HM-BUSY, process restart/reload, and permanent failure drop. If a false retry is reproduced, narrowly fix `retryable()` with an explicit refusal-first rule; keep offline recovery working.
- **Security PR C (conditional):** If long-history benchmarks are unacceptable, implement a measured query/indexing/rolling-counter approach with independent abuse review. Do not claim an in-memory cap fixes long-lived Sybil chain growth. No changes to signature, entitlement, envelope schema or identity semantics without a separate security/compatibility decision.
